# 悬浮计时窗与专注条

计时小窗采用与 v4 主程序一致的浅色主题：白底、深灰文字、浅灰辅助控件；暂停为描边按钮，下一段为深色按钮。分段条的已完成段为绿色，当前段为深色，其余为浅灰。任务名称保留两行空间；任务名、当前步骤和时间区域支持悬停查看完整任务信息。分段条表示当前位于第几段，不表示时间消耗百分比。

## 使用方法

1. 在主界面的计时区域打开悬浮窗。
2. 点击顶部的 **—**，最小化为专注条：只显示倒计时、暂停/继续和展开按钮。
3. 拖动时间或空白处，可以移动卡片和专注条。
4. 点击专注条右侧的展开按钮，恢复完整卡片；可以继续操作下一段、加 5 分钟或结束计时。
5. 顶部返回按钮显示主界面；**×** 或 **Esc** 仅收起小窗。收起小窗不会暂停或结束计时。

完整卡片为 300 × 252 逻辑像素，在 150% Windows 缩放下约为 450 × 378 屏幕像素，与参考模块大小接近。通过压缩留白和重新排版缩小窗口，保留 9 磅按钮文字、10.5 磅任务标题和 32 磅倒计时。专注条保持 232 × 64 逻辑像素，便于辨认时间与点击按钮。最小化仅改变窗口布局，不重置倒计时、不切换任务、不写入额外学习记录。最后一段的“下一段”仍会显示为“完成”。超时显示以“+”开头的时间；暂停状态会单独标识。

## 实现与验证

- `v4-desktop/TimerWindow.cs`：原生 WinForms 卡片、紧凑模式、命令按钮和高 DPI 布局。计时状态仍由主窗口与前端管理，数据格式未变。
- `v4-desktop/TimerWindowTests.cs`：独立模拟任务，检查暂停/继续、切段、加时、结束、最小化/展开不改变计时、字体边界和缩放布局。
- `v4-desktop/test-timer-window.ps1`：编译并运行上述测试，产出 `qa-output/timer-*/result.txt`。测试程序的 `--preview 日志路径` 可以打开独立模拟预览，不连接正式数据库。
- `v4-desktop/qa.js` 与 `qa-timetable.js`：桌面集成验收适配当前工作台和计时回顾弹窗，等待导入弹窗关闭后再重开。

从仓库根目录运行：

```powershell
npm test
powershell -NoProfile -ExecutionPolicy Bypass -File .\v4-desktop\test-timer-window.ps1
.\v4-desktop\build.ps1 -VendorRoot '你的 WebView2 vendor 目录' -OutputDirectory '.\v4-desktop\package-floating'
& '.\v4-desktop\package-floating\T计划 v4.exe' --self-test '一个尚不存在的绝对路径'
```

本机验收覆盖原生窗口点击、实际 150% 显示缩放、最小化/展开、暂停、加时、拖动，以及原生小窗命令与主界面的同步。布局测试中的额外 150% 缩放为控件尺寸模拟，不代表多显示器切换验收；Windows 10 的圆角回退尚未在独立 Windows 10 设备上实测。
